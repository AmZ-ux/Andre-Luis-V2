# UI/UX RULES — Transporte André Luis

## PRINCÍPIO

A aplicação deve parecer um aplicativo moderno, não um site administrativo antigo.

A experiência deve ser:

- simples;
- limpa;
- rápida;
- intuitiva;
- mobile-first;
- visualmente consistente.

---

# MOBILE

O celular é a principal plataforma do passageiro.

A interface deve ser projetada primeiro para telas pequenas.

Prioridades:

1. informação mais importante;
2. ação principal;
3. navegação;
4. informações secundárias.

Evitar excesso de informações simultaneamente.

---

# HIERARQUIA VISUAL

Cada tela deve possuir uma hierarquia clara.

Exemplo:

Página
↓
Título
↓
Resumo principal
↓
Ação principal
↓
Conteúdo
↓
Informações secundárias

Não transformar todos os elementos em destaque.

---

# DASHBOARD

O dashboard deve responder rapidamente:

- Onde estou?
- Quanto devo?
- Quando vence?
- O que preciso fazer?
- Existe alguma pendência?

A informação financeira principal deve possuir destaque visual.

---

# MENSALIDADES

A mensalidade deve deixar evidente:

- valor;
- vencimento;
- status;
- forma de pagamento;
- ação disponível.

Estados devem ser visualmente claros:

Pago
Pendente
Vencido
Cancelado
Isento

---

# STATUS

Nunca depender somente de cor.

Utilizar combinação de:

- cor;
- texto;
- ícone quando apropriado.

---

# CARDS

Cards devem agrupar informações relacionadas.

Não utilizar cards simplesmente para "encher" a interface.

Evitar excesso de cards aninhados.

---

# BOTÕES

Cada tela deve possuir uma ação principal claramente identificável.

Evitar várias ações primárias competindo entre si.

Ações destrutivas devem possuir tratamento visual apropriado.

---

# NAVEGAÇÃO

No mobile:

- navegação inferior;
- máximo de itens importantes visíveis;
- demais opções no menu "Mais".

No desktop:

- sidebar;
- agrupamento lógico;
- item ativo claramente identificado.

---

# ESPAÇO

Utilizar espaço em branco para separar grupos de informação.

Evitar:

- elementos colados;
- excesso de linhas divisórias;
- excesso de bordas;
- excesso de sombras.

---

# CONSISTÊNCIA

Uma mesma ação deve parecer igual em todo o aplicativo.

Um botão "Salvar" não deve ter uma aparência diferente em cada página.

Um card de informação deve seguir o mesmo padrão.

Um campo de formulário deve seguir o mesmo padrão.

---

# RESPONSIVIDADE

A interface deve adaptar o conteúdo, não simplesmente diminuir tudo.

Desktop:

informação pode ser distribuída horizontalmente.

Mobile:

informação deve ser reorganizada verticalmente quando necessário.

---

# TOUCH

Elementos interativos precisam ser confortáveis para toque.

Evitar:

- ícones minúsculos;
- links muito próximos;
- botões pequenos;
- áreas clicáveis menores que o necessário.

---

# PWA

A experiência deve funcionar como aplicativo instalado.

Evitar dependência de elementos típicos de desktop.

O usuário deve conseguir realizar as tarefas principais usando somente o celular.

---

# REGRA DE OURO

Antes de adicionar qualquer elemento visual, perguntar:

"Isso ajuda o usuário a entender ou realizar alguma coisa?"

Se não ajudar, provavelmente não precisa estar ali.
